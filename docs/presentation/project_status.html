SYNTHETIC DATA — PIPELINE DEMONSTRATION

Coastal Erosion Prediction Platform

1. Original Problem Statement

"Create a satellite-image analytics system to monitor and predict coastal erosion patterns. The solution should integrate spatial datasets such as maps, satellite imagery, terrain, rainfall, infrastructure, and field records to generate meaningful decision layers. The outcome may include risk maps, priority zones, dashboards, and validation using historical records or expert-labelled ground truth."

2. Actual Project Goal

Build a multi-source, spatial-temporal coastal erosion prediction system for the Chennai–Mahabalipuram Coastal Belt by processing five independent environmental/spatial domains.

3. Common Study Area

Chennai–Mahabalipuram Coastal Belt, Tamil Nadu, India. The architecture uses a shared configurable AOI polygon to unify features spatially.

4. Five-Domain Architecture

Why one paper is not enough: Coastal erosion is multi-faceted. Our architecture unifies:

1. Satellite Imagery: Spectral indices, land/water classification.
2. Shoreline History: Historical shoreline movement.
3. Terrain: Elevation, slope, distance to shore.
4. Rainfall/Weather: Cumulative rainfall, wind speed.
5. Ocean Conditions: Wave height, storm surge.

5. Current Selected Satellite Paper

Title: Geoinformatics and Machine Learning for Shoreline Change Monitoring: A 35-Year Analysis of Coastal Erosion in the Upper Gulf of Thailand
Why Selected: Provides clear implementation details for RF-based spectral classification (NDVI, NDWI, MNDWI, SAVI) which perfectly matches our Domain 1 needs.

6. Synthetic-Data Architecture & Fusion

For Phase 1, we implemented a deterministic data generator producing realistic (but synthetic) data for all 5 domains across 100 coastal segments and 24 time periods. These are standardized and joined spatially and temporally into a combined_ml_inputs.csv layer.

8. GIS & Dashboard Output

Outputs include Priority Zones (High, Medium, Low risk segments) generated by combining predicted erosion change with external factors like storm surge. map_data.geojson serves as the rendering layer.

9. Current Implementation Status & Real-Data Migration Plan

  • Done: Scaffolding, Synthetic Data Generator, Join Pipeline, ML Training & Inference, API endpoints skeleton.
  • Limitations: Currently completely synthetic. Deep Learning not yet integrated.
  • Migration Plan: We will implement real-data adapters (RealSatelliteAdapter, RealWeatherAdapter) domain by domain, allowing seamless transition to real-world validation.
